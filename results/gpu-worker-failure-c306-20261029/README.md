# Bounded synthetic GPU worker failure validation

One source-bound run used a randomly initialized 4,464-parameter one-layer GPT-2 with a 1×2 input on an NVIDIA GeForce RTX 2070 SUPER. PyTorch's allocator cap was 512 MiB. This is a failure-handling exercise, not a throughput, model-quality or device-capacity benchmark.

The direct synthetic trace phase ran success, a deliberately raised cancellation after a forward, and success. Each session reported a 64-byte capture retained through synchronization, then weakref-checked release of the capture, input, output and logits before a second synchronization and trace-claim release. This direct trace phase is separate from the fixed worker, which has zero trace claims; it does not establish a trace-enabled service.

The fixed worker reported baseline success, accepted a cooperative cancellation after its forward returned, and then completed another request. Its final bounded forward deliberately raised `torch.OutOfMemoryError` in Python. This was **not actual VRAM exhaustion or an allocator-generated OOM**. The public failure was `WorkerSynchronizationError`; the private error type was `OutOfMemoryError`. The worker became unsafe, retained two accounting claims and refused a later request. Cancellation did not preempt a GPU kernel.

The ten saved allocator/device-free samples are taken after guarded synchronization at safe points. The maximum sampled allocated and reserved values were 67,131,904 and 69,206,016 bytes; minimum sampled free was 7,322,206,208 bytes. After baseline, cancellation and post-cancel success, all three values were equal at those respective samples. These are point observations, not allocator peaks, continuous monitoring or a device-wide cleanup proof. There was no CUDA query after the worker became unsafe.

The direct owner and controller exited 1, as expected for the deliberately unsafe terminal; the supervisor recorded no timeout and Job counts `[[0,0],[1,0]]`. Its result was marked incomplete, the unsafe marker was present and no clean attestation was created. A later qualified two-phase operator recovery preserved the original evidence, retained a non-clean sentinel through independent review, and then released the coordinator hold after a separate readback. Neither process exit nor recovery proves native CUDA cleanup, escaped-process absence or future admission. Every future owner still needs its own admission.

An early live directory listing was taken concurrently with the controller wait and omitted later files. The initial statement that no simulated-OOM terminal had been observed was corrected after the wait completed: the closed directory contained both the terminal and injected-OOM records. The observer's once-per-second `terminal_record_seen` flag also remained false; the separately saved terminal and controller result establish its presence. The listing race and the polling flag are not evidence that the terminal was absent after exit.

`stages-redacted.jsonl` and `result-redacted.json` remove run identifiers, process identities, device UUID and local paths. The two incident audits and the selected recovery records are path-free copies of independent saved reviews. Their hashes of private original records are commitments, not publicly replayable originals. The raw private evidence remains retained separately.

`source-snapshot/` contains the exact 26 source files declared by the executed owner and six CPU-test files; `source-manifest.json` records their SHA-256, Git blob IDs and modes. The executed source was local commit `c30642c18fa2c7b37e673af2d7b4041309b83966`, tree `4eaa9bac6f9b8c035d0b085d610b197070d756be`; that commit is not currently reachable on GitHub. This snapshot permits byte inspection but is not a standalone Git checkout and does not independently establish commit ancestry. Two source module docstrings still say “disabled”; the actual executed gate values in the snapshot were enabled. The separately coordinated one-shot is over.

Run `python replay_public.py` to check package hashes, source snapshot hashes, projected stage order, sample arithmetic and consistency with the path-free audits. This replay cannot independently verify private raw records, live process state, CUDA behavior or recovery. `SHA256SUMS` inventories the published bytes; it is not a signature.
