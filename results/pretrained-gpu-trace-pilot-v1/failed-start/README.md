# Five-token pretrained GPU trace pilot: incomplete first attempt

The first source-bound attempt on 29 October 2026 recorded no completed model forward or checkpoint load. Its saved diagnostic reports a `TypeError` at load-phase startup, zero completed forwards, no cleanup attestation and an unclean owner exit. The directly observed controller also exited nonzero. The saved post-exit point still had the unsafe marker; the prior owner was absent from the management process query. Device setup, synchronization and logical admission had already occurred, so this was not a pre-device failure.

The diagnostic did not preserve an exception message or traceback. An independent CPU reproduction of the exact source found that the CLI supplied a string directory to a phase writer expecting a path object; it reproduces the same error and phase boundary, but is an inference about the original line rather than direct traceback evidence. Source ordering puts checkpoint loading after that phase-start record. [PR #662](https://github.com/EastonSell/model-looking-glass/pull/662) corrects the interface and adds a fake-device test through the actual string-argument owner entry.

The retained [independent audit](failed-start-audit.json) binds the public source commit and hashes of the private controller, owner, supervision, failure, and outcome records. It reports the observed management free-memory endpoints of 7,410,286,592 bytes before and 7,411,335,168 bytes after. These are sampled device-wide points, not peaks or proof of native CUDA cleanup. The audit is a source-and-record consistency check, not authentication of the original process or proof of descendant or native-context teardown.

There are no trace, logit, latency, or phase-memory results from this attempt. Its private evidence is retained. A separately authorized successor requires qualified resolution of the marker and a fresh reviewed admission; the failed attempt is not a successful profile or a basis for automatic retry.
