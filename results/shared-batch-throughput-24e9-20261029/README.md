# One shared-owner serial and grouped measurement

This is a single fixed-order, closed-loop observation, not a general capacity or production-throughput result. The executed owner and protocol were frozen locally before the run at commit `24e9de6cc4025432ff3f4b2a72f1026213a843d6` and tree `10cbe13d7c41a5cd302c3db16b9f793653697edd`. The [35-file protected source snapshot](executed-source/) is published after the run and is a byte-preserving archive; it does not imply that the original local commit was public when measured. It is not the complete historical Git tree or a self-contained runnable environment. The source underwent same-session functional calibration and held-out validation, not a prior standalone source-matched capacity profile.

The workload uses `distilbert/distilgpt2` revision `2290a62682d06624634c1f46a6ad5be0f47f38aa`, float32 eager attention, seed 2026102808 and eight all-one-mask rows `[50256, n, n+100, n+200]` for n = 103–110. The GPU was an RTX 2070 SUPER; Python 3.11.15, PyTorch 2.8.0+cu128 and Transformers 4.57.3 were used. See [summary.json](summary.json) for exact denominators, host-stamped intervals and counter values.

The closed v7 attempt used one resident DistilGPT2 owner and a fixed, closed-loop workload of two clients with four 1×4 requests each. The measured serial window contains eight observed [1, 4] model entries; the grouped window contains four observed [2, 4] entries and four two-member broker group claims. Both windows report final synchronization and eight completions. Independent full-row replay found all eight paired outputs within 1e-6 + 1e-5 × abs(serial reference) and found the within-group swap controls distinguishable.

The single serial-then-grouped pair recorded wall rates of 0.78994 and 0.62517 completed jobs/s, respectively, a grouped/serial ratio of 0.79141. These wall intervals include different control and relay/broker paths and instrumentation; this fixed-order exploratory pair does not establish a general batching speedup, device-only latency, sustained fairness, or an isolated-device result. The source stamps use CPU monotonic timestamps for model entry and an owner finish hook whose synchronized argument was observed; they are not CUDA-event GPU durations. Host and device-wide free-memory snapshots and process-local allocator peaks have separate scopes.

The nominal boundary is the head request’s broker-ready timestamp plus 100 ms. Peer relay ingress at or before that boundary is eligible only if it is already queued when checked and satisfies team and compatibility rules; a concurrent arrival is not guaranteed to be captured atomically. The peer may already be in the relay before the head becomes broker-ready. The fallback is dispatcher-observed, not a hard deadline on broker admission, claim, or response. For the four groups, the peer entered the relay 523.696, 455.969, 495.269, and 465.721 ms before the nominal head boundary, but became broker-ready 265.375, 335.156, 309.326, and 382.006 ms after it. Group-claim returns occurred 312.801, 396.491, 359.254, and 439.187 ms after that boundary. The owner submitted the eligible peer before dispatch, and the broker checks a compatible two-row cohort before singleton fallback. These observations do not establish that requests waited at most 100 ms or that the fallback fired in these four groups.

The direct owner and controller records report clean exit and a waited controller exit; a coordinator OS point found marker/attestation absent, and the scheduler released this slot. Those are scoped observations, not proof of native CUDA teardown, descendant absence, device isolation, or future admission. The coordinator reported a brief CPU-only check during controller lifetime. Reviewers also reported CPU-only checks and streaming verification of a 122,677,157-byte archive with original-file reads. A separate reported Decimal audit streamed a 132,831,744-byte logits file twice for hashing and read another 19,534,080 bytes. Both saved reports had filesystem timestamps during controller lifetime; actual process start/end times were not independently retained. These are operator/file-time observations: physical I/O was not measured, and no durable UTC-to-window-clock mapping establishes overlap with either measurement window or an effect on it. Other background disk/I/O activity was not measured. Separate source/custody and resource audits passed within their stated scopes.
