# Answer-format feasibility: development phase

The fixed development screen is **ineligible** for selecting a format family: neither statement nor question has at least three facts whose factual city is the unique full-vocabulary top token under all four prefixes. The prescribed held-out phase remains required even with this underfill; no edit target was selected and no edit was attempted. This development result concerns these four facts and fixed templates, not all possible answer formats or the model's broader knowledge.

The independent saved-logit reader found a unique top on all 32 rows and the factual city as top on 4/32: 0/8 with no prefix, 3/8 with the neutral prefix, 1/8 with the Spain–Madrid example, and 0/8 with the Sweden–Stockholm example. The Spain condition topped ` Madrid` on 6/8 rows and the Sweden condition topped ` Stockholm` on 5/8; all eight predeclared within-template D contrasts were positive (+12.679 to +16.558). D is the change in Madrid-versus-Stockholm log odds between the two example prefixes. These compare the two fixed prompt contexts. Each changes both example country and city, and the shorter no-prefix condition differs in position and length, so this result alone does not identify a copying mechanism, establish generated answers, or support a population claim. The held-out templates reuse the same facts and are not held-out facts.

The [raw attempt](attempt/phase-record.json) retains every full-vocabulary float32 row in shuffled execution order, the row journal, numeric results, decoded tops and cooperative process/custody reports. The [independent scores](independent-scores.json) and [owner comparison](independent-audit.json) re-read all saved rows and compare the writer's outcomes and token decoding; their scripts need Python, NumPy and the pinned tokenizer. The comparison checks saved data, not whether the model actually executed as reported. Execution, teardown, custody and chronology are cooperative observations, not authenticated proof.
