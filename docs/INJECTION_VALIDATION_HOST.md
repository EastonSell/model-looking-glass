# No-model replay validation host

The one-shot host retains and reaps the gated validation root through the
reviewed outer observer. It holds the verified source, asset, configuration
and empty-bytecode-prefix handles through that observation. A failed or
ambiguous launch keeps its rooted custody; the cooperative hold does not
cover forced process death or every native return boundary.

The host accepts, in order, the validation config path, driver source path and
SHA-256, the immutable public host-source URL and SHA-256, and the public
replay-plan SHA-256. A trusted caller must execute these exact host bytes from
a hash-before-execution bootstrap with the direct base interpreter and
isolated flags, then release the start token. Its source hardcodes the reviewed
driver and plan digests and checks both before loading the driver. The host
then verifies its published
source, the plan and all source/public/asset inputs, current curated runtime,
private parent, diagnostic budget and unclaimed ledger before launching. It
does not read the concealed site or split, make a claim, load the model or
perform a forward.

The host terminal remains `awaiting_host_exit`. Its caller must retain the
actual host process handle, establish PID and creation time, observe zero exit
and reap, and recheck the terminal and full nested records with
`check_host_terminal`. That check is a saved-byte consistency check; it does
not itself prove the caller observed the exit. The caller must also account for
all final diagnostic files before any later one-use claim.
