# Injection CPU supervisor exit observation

The same outer observer can watch either a preparation supervisor or an
execution supervisor. It does not prepare a split, publish evidence, select a
site, or authorize model work. A source-first trusted caller must verify the
published observer, Windows Job implementation, supervisor and other executed
dependencies before importing them, bind the exact operation and private
configuration, establish access controls, and provide a fixed command. The
supervisor terminal path must be absent both before spawn and immediately
before the startup token is released. The terminal verifier must bind the
retained supervisor PID and process birth identity to the exact terminal and
its child/cleanup records. The
direct supervisor must wait for the prescribed startup token before it can
create an active child or perform study work.

The observer creates one fresh private output directory and an exclusive start
record, roots the Job and process handles, assigns the still-gated process to
the Job, establishes source protections and process birth identity, and only
then releases its start token. It waits on the retained process handle and
requires a zero exit, a reaped process, zero active outer Job members, and
successful Job drain, Job close and process-handle close. It then calls the
trusted bounded terminal verifier, rechecks the exact source/configuration and
terminal bytes, and writes a digest-only `observation.json`. The preparation
terminal must bind the six audited private preparation files; the execution
terminal must bind its supervised child, score and cleanup evidence. This
observer does not itself verify the scientific content of either terminal.

If the start signal may have been delivered and the supervisor has not been
reaped, the observer retains process and Job custody instead of killing a
supervisor that might own the only handles to a nested Job. An interrupted or
uncertain Job drain, Job close or process-handle close is never retried in the
same process. The attempt remains incomplete and cannot be retried or used to
justify another allocation. Partial files and uncertain processes must be
retained for the trusted custodian's reconciliation.

The observation is a cooperative local record, not proof against another
process using the same account. A separately retained observation of the outer
observer's own clean return or exit is required: an observation file can exist
after a later error or ambiguous flush. The caller must verify private paths,
source and runtime before and after, account all retained files within the
existing phase allowance, and independently verify publication and the
cross-track gate before any affected forward.
