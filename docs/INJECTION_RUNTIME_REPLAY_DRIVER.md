# Prospective injection replay validation driver

This source provides the no-model validation process for the separately
published injection runtime compatibility plan. Its four command-line modes
are gated validation parent, validation observer, validation operator and
source-first validation root.
They do not claim the injection phase, read the concealed site or split,
load a model, or perform a forward. The helper functions for later claim and
replay remain components, not independent authorization to run them.

Before using the validation path, a trusted source-first operator must verify
the exact immutable plan, every named source and public input, the offline
assets, the recorded curated environment, and the private output directory.
It must retain and duplicate the source, asset, configuration and protected
empty-bytecode-prefix handles into each gated process before granting it. The
driver uses a closed source-only import graph and rejects unbound project
imports. The validation child uses the direct base interpreter and the frozen
discovery bootstrap; its exact approved dependency site is part of the test.

The validation parent checks that the injection phase has not been claimed,
then runs the child under the bounded supervisor. It rechecks source, runtime
and diagnostic accounting and produces a private parent terminal. The outer
observer retains the parent's process handle and birth identity, verifies the
child's saved supervisor record and reaping, and writes a private observer
terminal. The operator observes that observer in turn and writes a private
`validation-exit.json` with status `awaiting_operator_exit`. The source-first
root separately retains and reaps that operator and verifies the nested
terminal. The root's own successful exit must then be observed independently.
Saved files alone cannot establish that exit or authorize a phase claim.

The no-model diagnostic root is within the existing 4 MiB injection-phase side
reservation. A full fresh inventory, including the operator exit observation
and any partial files, must be reconciled immediately before the single phase
claim. The validation source checks the original discovery runtime and the
separately published held-out runtime; their differing system-environment
fingerprints remain a disclosed prospective deviation, not evidence that the
two environments are equivalent.

The outer Windows Job permits breakaway for a separately supervised inner Job.
If outer observation fails, this driver retains its rooted leases and process
objects in quarantine; an empty outer Job alone does not prove that a helper
or inner descendant has stopped. The cooperative hold covers ordinary console
interrupts, not forced process termination or every possible native return
boundary. An interrupted or ambiguous attempt must be preserved and must not
be retried as a fresh claim.
