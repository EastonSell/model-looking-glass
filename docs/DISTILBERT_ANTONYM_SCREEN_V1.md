# Bounded antonym baseline screen owner

This owner implements only the 12-row baseline screen in the
[antonym protocol](DISTILBERT_ANTONYM_PREFERENCE_V1.md). A separately
published and reviewed owner is required before any edit, held-out action or
locality action. An ineligible screen is a result and is not retried with
substituted cases.

The owner adapts the previously reviewed color-preference CPU supervisor and
direct-supervisor observer. It reuses their bounded checkpoint staging,
one-shot process and failure handling, state restoration checks, runtime
witnesses and full-f32 event envelope; the inherited cooperative transport
schema names contain `color` but the source/manifest and outputs identify this
antonym study. The adapter reconstructs the entire 55-row tokenizer inventory
against the pinned fast tokenizer before loading any study input. It permits at
most 12 screen starts, uses eager CPU float32 with one deterministic thread,
and retains the entire 30,522-token mask-logit row for each completion.

The saved-f32 selector requires a strict unique factual top on discovery only
and an exact factual-minus-cue margin greater than rational `1/10` on all three
screen rows. It retains all rows, accepted alternatives, full-vocabulary ranks,
factual and cue probabilities and combined pair mass. A separate independent
reader checks all decisions and the pre-forward adaptive tiny-tail regression;
an unresolved numerical disagreement is indeterminate. A display rounded to
0.10 is not a threshold decision.

The prelaunch record binds the fixed case, planned exposure and named-public
comparison bytes, reconstructs a current named-public scan and checks optional
separately pinned sources. It compares complete and one-SEP-removed rows in
both prefix directions. The supervisor rechecks current official main at the
launch boundary and fetches a missing exact Git commit object if necessary;
unrelated main changes do not by themselves invalidate the study. The worker
reconstructs the launch scan before model loading. These are named-public
currentness checks, not a claim about unknown, private or pretraining history.

The screen uses the earlier source-bound direct-child supervisor, validation
marker and separate supervisor-exit observer. A partial stage, lost child handle,
uncertain cleanup or numerical disagreement remains incomplete/indeterminate
and is not silently retried. The evidence and source checks are cooperative
saved-record observations, not process-tree or execution attestation. The
source, cache, dependency site, scratch and run paths must meet the existing
disjointness and fresh disk-space checks. This note specifies an owner and does
not report a pretrained result.
