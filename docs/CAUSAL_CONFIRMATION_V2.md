# Synthetic causal-debugger protocol v2

**Status: proposed protocol; at drafting, no v2 held-out inputs or outcomes have been generated or evaluated.** This document specifies a future CPU experiment and its release gates. It does not change or replace the [v1 protocol](CAUSAL_PROTOCOL_V1.md), its exploratory results, or their recorded exposure history. A separate implementation, independent review, and a frozen run manifest are required before execution.

The question is whether a fixed sparse-trace policy can identify the **block interval** containing a known artificial change and whether a prediction fitted on discovery inputs matches the effect of a specified patch on new inputs. This is a bounded test of instrumentation and prediction, not an explanation of a pretrained model or its reasoning. In this feedforward testbed, the first changed complete block state is expected to identify the injected block whenever the change survives to that state; this structural advantage makes localization largely an instrumentation sanity check.

## Testbed, ground truth, and units

- Use CPython 3.11.15 and PyTorch 2.8.0+cu128 in eager CPU float32, one PyTorch intra-op thread, evaluation mode, route 0, no training, and one input per forward; the CUDA-enabled build is not permission to run this CPU study on the GPU. Run every model forward inside `torch.no_grad()`; evaluation mode alone does not disable autograd. Instantiate `TinyResidual(width=8, depth=4)` separately for each of the six fixed model seeds **31201, 31202, 31203, 31204, 31205, 31206**. Within `torch.random.fork_rng(devices=[])`, seed `torch.random.default_generator` with that model seed, construct the model and call `.eval()`; do not seed CUDA. Save each model-state hash and the exact source, runtime, and settings. None is v1's model seed 2301.
- Cross **each** model seed with all nine fixed injection configurations: blocks 1, 2, and 3, each at `branch.0`, `activation`, and `merge`. Thus there are 54 model/configuration cells, not 54 independent models. For each model, the custodian privately permutes these nine configurations using a cryptographically secure random shuffle and publishes a salted commitment to the complete schedule before any discovery forward. The cell ID contains only the index of this private permutation, not an ordered site identity or ground-truth rank. The selection policy must not receive its injected block, operation, or schedule.
- In an active cell, the model's existing `perturb` argument adds `a * s(x)` to element `[0, 0]` immediately before the named tap, with strengths `a` in **{0.25, 0.75}** and `s(x) = +1` when `x[0,0] > 0`, otherwise `-1`. Inputs below never have zero in that coordinate. Both strengths are evaluated on each same input. The polarity rule is deliberately **given** to the predictor; any gain from using it is information supplied by this artificial experimental design, not discovery of a natural computation.
- The full ordered observed trace contains exactly `block.0.output` through `block.3.output`, invocation zero, with the expected CPU float32 `[1,8]` values. The intervention candidates are only the complete outputs of blocks 1, 2, and 3. Block 0 is a known upstream negative control; block 3 is the complete state immediately before the head and is also the downstream rescue control. Candidate scoring is at the block-interval level. Do not call a correct block selection recovery of the specific within-block operation.
- For one model, reuse its 16 discovery inputs and 16 separately generated held-out inputs across its nine configurations and both strengths. Inputs are distinct across models as well as across splits. Repeated strengths and configurations on the same model/input are paired, not independent observations. Model-seed summaries are conditional on these generated inputs and fixed initializations; differences between model-level means combine differences in models and their inputs.

Compute a model-state SHA-256 in sorted `state_dict()` name order. For each tensor, serialize `{"name": name, "shape": list(tensor.shape), "dtype": str(tensor.dtype)}` with CPython 3.11.15 `json.dumps(..., sort_keys=True, indent=2, allow_nan=False)`, UTF-8, and one trailing newline; take the tensor's detached, contiguous CPU `uint8` byte view in storage order. Update the digest with the 8-byte unsigned big-endian header length, header bytes, 8-byte big-endian tensor-byte length, and tensor bytes. Record the machine byte order and runtime build: the hash identifies these actual tensor bytes, not a promise of cross-platform bitwise identity.

## Prerequisites and finite resource limits

Before preparing the v2 held-out set, exercise the proposed runner and controls on **different** model seeds and inputs that do not overlap v1. Retain the exact float32 pilot input tuples and their digest as a mandatory exclusion set when both v2 splits are later generated. This development-only pilot may measure CPU time and peak host memory to decide whether the specified job is feasible; it must not evaluate or tune against any v2 held-out data. Preserve pilot failures separately. If the pilot shows the proposed work cannot fit the available budget, stop and version a smaller protocol before sealing the v2 schedule; do not silently reduce counts, precision, strengths, controls, or thresholds.

The runner must support the existing native `TinyResidual` perturbation together with one exclusive `ActivationIntervention` per patch forward, a separate read-only `TraceSession` per sparse trace forward, and a separate exclusive `ActivationCapture` per private single-target integrity forward. Do not nest independent sessions on the same model. Verify known toy cases for injection location, hook cleanup, whole-output patching, repeated invocation rejection, exception handling, and exact no-op output preservation before the run. No new composite hook is assumed. Capture is capped at **4 events and 128 logical tensor bytes per sparse trace**; this does not count temporary allocations, metadata, or process peak memory. Use `ActivationCapture` with `max_tensor_bytes=32` and `max_invocations=1` for each private integrity capture. Execute at most one model at a time. Count all root forwards, including discovery, controls, integrity checks, failed attempts, and held-out evaluation; the recorded run has a hard cap of **60,000** root forwards and a 64 MiB total artifact budget. Hitting a cap is a failed or incomplete run, not a reason to drop controls or cases. Reuse an already measured clean trace or repeated measurement only when model, input, route, and execution settings are identical; the CPU pilot must confirm the full specified workload fits the cap.

The minimum planned schedule is explicit. The **6 × 32 = 192** model/input pairs each use one clean sparse trace and one repeated clean sparse trace: **384** forwards. Each of the **6 × 9 × 32 = 1,728** model/configuration/input triples uses one private clean capture at its hidden target, reusable for its two strengths: **1,728** forwards. Each of the **6 × 9 × 32 × 2 = 3,456** active conditions then uses 16 forwards: one perturbed sparse trace, one private perturbed target capture, three clean-to-perturbed patches, three reverse patches, three nulls, three identity patches, one upstream patch, and one clean verification after the complete set. This is **55,296** forwards, for **57,408** total, leaving **2,592** below the cap for explicitly recorded extra attempts or checks. A block-3 clean-to-perturbed candidate patch is the downstream control and is not rerun. The two clean sparse traces are also the no-injection comparison. No failed attempt is erased to recover budget. If implementation adds any other required forwards, its counted plan must still fit the cap before sealing; otherwise stop and revise the protocol before the run.

## Case construction and procedural holdout

Use 16 discovery and 16 held-out vectors per model. The discovery root is the integer `2026102803` encoded as 32 unsigned big-endian bytes. Before discovery, a custodian draws an independent private 32-byte held-out root with `secrets.token_bytes(32)`. The custodian also draws independent 32-byte nonces for the site schedule and the later per-case prediction commitment. Equal nonces must be rejected; unequal values alone do not prove independent or high-entropy sampling.

The pilot exclusion record is `{"inputs": inputs}`, where `inputs` is an array of objects with exactly `case_id` and eight float32 `values`, sorted by case ID. Reject duplicate IDs and duplicate float32 tuples, treating signed zeros as equal. Its digest is SHA-256 of the canonical JSON defined below. Retain the record itself so the exclusion test can be independently repeated.

The following deterministic construction defines each eight-dimensional case without model execution. For each split in discovery-then-held-out order, model seeds in the order above, and case index `i` from 0 through 15, start `attempt=0` and calculate:

```text
d = SHA256(b"MLG-v2-cases\0" + root + model_seed.to_bytes(8,"big")
           + split_byte + i.to_bytes(2,"big") + attempt.to_bytes(2,"big"))
x[0] = ((d[0] & 15) + 1) / 16 if i is even else -((d[0] & 15) + 1) / 16
x[j] = ((d[j] & 31) - 16) / 16, for j = 1,...,7
```

`SHA256` returns its 32 digest bytes; `split_byte` is `b"D"` or `b"H"`, and `root` is the corresponding 32-byte root. These values are exactly representable as float32. Even indices give eight positive-polarity cases and odd indices eight negative-polarity cases per model/split. Check complete float32 tuples for overlap with every v1 input, every retained pilot input, and every previously accepted v2 input; treat positive and negative zero as equal. On a collision increment `attempt` and recompute, up to 65,536 attempts; failure to find a new vector invalidates preparation. The ordering rule makes collision resolution reproducible. Case IDs are `v2-m{seed}-d{index:02d}` or `v2-m{seed}-h{index:02d}` and do not encode the private site. Save the actual bytes and identities after reveal, not just a generator name.

Before any discovery forward, the custodian must atomically publish a public pre-manifest containing the committed protocol and implementation revisions and hashes, the retained pilot-input digest, model seeds and model-state hashes, all discovery IDs and values, fixed settings, the fixed polarity rule, and separate salted SHA-256 commitments to the full held-out cases and the full site schedule. Record a self-reported UTC time and retain an independent witness or external timestamp if available; hashes, local clocks, and source order alone do not establish a trusted timestamp.

For reproducibility, the commitment bytes are fixed as follows. Canonical JSON means CPython 3.11.15 `json.dumps(value, sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False).encode('utf-8')`, with finite JSON numbers only and no trailing newline. The `context` object has exactly `protocol_id` (`synthetic-causal-v2`), `protocol_sha256`, `source_revision`, and `model_state_hashes`, the latter an array of `{"seed": integer, "sha256": lowercase_hex}` in the model-seed order above. Let `context_sha256 = SHA256(canonical(context)).hexdigest()`.

- The held-out record is `{"context_sha256": context_sha256, "cases": cases}`, where `cases` is ordered by model-seed order and case index and every element has exactly `case_id`, `model_seed`, `split` (`heldout`), `index`, and eight float32 `values`. Its commitment is `SHA256(b"MLG-v2-holdout\0" + heldout_root + canonical(heldout_record)).hexdigest()`. The private held-out root is both the generation root and this commitment's salt.
- The schedule record is `{"context_sha256": context_sha256, "assignments": assignments}`, ordered by model seed then cell index. Cell IDs are `v2-m{seed}-c{index:02d}` for indices 0 through 8. Each assignment has exactly `cell_id`, `model_seed`, and `injection_node`, where the node is one of the nine allowed full tap labels and each appears once per model. Its commitment is `SHA256(b"MLG-v2-schedule\0" + site_nonce + canonical(schedule_record)).hexdigest()`.
- Let `M` be SHA-256 of the **entire** canonical public pre-manifest, and let `F` be SHA-256 of the **entire** canonical public prediction freeze described below, which includes `M`. The private concrete-prediction record is `{"pre_manifest_sha256": M, "freeze_sha256": F, "predictions": predictions}`. Order its entries by model seed, cell index, held-out case index, strength ascending, then site block 1, 2, 3. Each entry has exactly `model_seed`, `cell_id`, `case_id`, `strength`, `site`, `polarity`, `polarity_prediction`, `constant_prediction`, and `zero_prediction`. Its commitment is `SHA256(b"MLG-v2-predictions\0" + prediction_nonce + canonical(prediction_record)).hexdigest()`.

All three roots/nonces are private 32-byte values until reveal. Store `context`, the two initial commitments, `M`, `F`, and the later prediction commitment with the evidence. Verify every revealed byte sequence and digest independently; reserializing arbitrary JSON with another runtime is not assumed equivalent.

Held-out values, roots, schedule, and nonces stay outside the checkout and out of the investigator's normal view until the prediction and evaluation phases finish. A separate custodian/executor receives the private schedule and performs model calls; the selection investigator receives only opaque cell IDs, the prescribed clean and perturbed sparse values, and sanitized observation metadata. Request IDs, filenames, metadata, logs, and errors visible to the investigator must not encode the true target; a failure yields an opaque cell ID and a generic failure status, while its detailed exception and private integrity data are retained by the custodian for later audit. The custodian may generate and validate vectors, but **no held-out model forward of any kind** may precede the global prediction freeze. This is procedural separation: agents share one OS account and cannot claim enforced secrecy. Inferring a candidate block from discovery observations is the intended task; disclosure means exposing the custodian's ground-truth record, private inputs, or outcomes outside the prescribed phases. If such disclosure occurs, mark the attempt unblinded/exploratory and retain the failure or disclosure. After evaluation, reveal the exact cases, schedule, roots and nonces and verify the commitments. These commitments cannot prove entropy, uniform sampling, or secrecy. A public revealed suite must not be reused as an unexposed holdout.

## Discovery, baselines, and frozen predictions

Run all discovery work for all 54 cells before any held-out model forward. If a model is unloaded between phases, reinstantiate it from its fixed seed and require its state hash to equal the pre-manifest before proceeding. Within each cell and strength, pair a clean sparse trace with a perturbed sparse trace for the same discovery input. Check exact repeated-clean equality and full metadata/order/shape agreement; a difference at upstream block 0, missing event, or invalid shape invalidates that cell. Use exact tensor equality on this CPU protocol. Record the first observed unequal boundary and last equal boundary for every pair; if there is no difference, record an observation miss. An active nonzero injection that is masked before any sparse output is an observation miss, not a negative example or an omitted trial. Report missed-pair counts separately; the cell's policy may still select from other pairs and abstains only when no eligible difference is seen in any of its 32 discovery pairs. For each input and configured hidden target, the custodian also makes private, separately bounded clean and perturbed captures at that target. Compare the perturbed tensor exactly with the clean tensor plus the prescribed float32 delta at `[0,0]`; verify every other element is unchanged and the target element actually changes. A failure is an invalid injection, not a masked observation. Reuse the clean target capture across the two strengths when its model, input, and target are identical. Keep these target-identifying integrity records private until the ground-truth reveal.

For each cell choose sites using discovery only:

1. **First changed:** select the eligible block most often first unequal across both strengths and all discovery inputs; ties go to the lower block. If no eligible difference is seen, abstain.
2. **Magnitude:** rank eligible blocks by mean L2 norm of paired clean/perturbed sparse-output differences over exactly the same discovery pairs; ties go to the lower block. For each pair and block, flatten the eight float32 values in storage order, convert each value to a Python binary64 float, and compute `math.sqrt(math.fsum((float(clean_i)-float(perturbed_i))**2 for i in range(8)))`. Take `statistics.fmean` of those 32 norms in case-index order, with strength 0.25 then 0.75 for each case. If all scores are exactly zero, abstain.
3. **Random:** report the uniform expectation over all three eligible blocks, computed from all three predeclared locations, without choosing the best after seeing outcomes. A hypothetical single draw has block-hit probability 1/3 under this fixed uniform baseline. This exhaustive expectation uses three evaluation sites; it is not the compute cost of one sampled site.

Every policy receives the same discovery traces and the same per-location patch budget. The random policy ignores trace values. For each eligible block, strength, and discovery input, run a whole-output clean-to-perturbed patch with a clean source from that same input and a perturbed base. For scalar `m(z)=z[0,1]-z[0,0]`, compute the subtraction in float32 and convert the result to a Python binary64 float. Define the patch effect `e = m(patched)-m(perturbed)` using Python binary64 subtraction. The predicted effect for a held-out input at that same site and strength is `statistics.fmean` of `e` among the eight discovery inputs with the **same supplied polarity**, in case-index order. Fit the comparison constant-mean predictor using `statistics.fmean` of all 16 discovery effects at that same site and strength in the same order; the zero predictor always predicts zero. No held-out outcome, known injection coordinate, or later result can change these rules. Score these three predictors on the **same site's effects**; comparing prediction errors across different sites alone confounds prediction difficulty with effect magnitude.

Publish a complete machine-readable freeze containing, for every cell, the first-changed and magnitude choices or abstentions, the fixed uniform distribution over the three random comparison sites, all site/strength/polarity means, constant and zero baselines, discovery measurements, tie and zero rules, patch source and base definitions, all control definitions, the metric, and the committed evaluation-set identity. The custodian uses the frozen functions and private held-out inputs to form every concrete per-case prediction **without a model forward** and durably publishes a salted commitment to that exact prediction record. The public prediction artifact and the commitment must both be flushed and saved before the first held-out forward in any cell. Verify their exact hashes after reveal. The frozen function may use `s(x)` because that polarity is part of the stated input-dependent intervention; its use is not a model-discovered feature. If selection abstains, preserve the abstention and freeze no fabricated candidate effect.

## Held-out interventions and controls

For every held-out model/input, configuration, and strength, record the clean and perturbed full two-logit outputs and the frozen per-case predictions. At **each** eligible block run the same-input clean-to-perturbed patch and save the full patched logits and scalar effect. Also run the corresponding perturbed-to-clean reverse patch; do not assume the reverse effect is the negative of the forward effect in a nonlinear network. The exhaustive site sweep defines the fixed random expectation and shows whether several locations have the same effect; it does not license selecting a new candidate after evaluation.

For every relevant site, perform a null intervention and a same-run self-patch on the perturbed base, requiring exact full-logit equality with that base. Patch `block.0.output` from clean into perturbed as an upstream negative, also requiring exact full-logit equality with the perturbed base. Patch clean `block.3.output` into the perturbed base as the late downstream control, requiring exact equality with the clean full logits. Save **all** these control logits, baseline logits, source/base identities, and raw deltas. After each complete intervention set for one model/input/configuration/strength, verify a fresh clean pass after all hooks are removed. A failed required equality invalidates that cell and remains in the record.

Separately compare two no-injection clean runs on each model/input and require complete, exactly equal sparse traces and logits. Report a false detection if their comparison claims any changed sparse boundary, and also report whether the aggregate first-changed or magnitude selection policy makes a non-abstaining selection on the no-change collection. Do not count repeated no-injection copies across the nine configurations or two strengths as independent negatives. Report discovery and held-out negatives separately. A zero task effect or a masked nonzero injection is a valid observed outcome, never grounds to choose a new site, input, or strength.

In this architecture the site-wise patch map is a step function. For a patch at a block **before** the injected block, the clean and perturbed source states are identical: the clean-to-perturbed result must equal the unpatched perturbed full logits, and the reverse result must equal the clean full logits. At the injected block or any later block, the clean-to-perturbed result must equal the clean full logits, and the reverse result must equal the perturbed full logits. The custodian checks these equalities against the hidden ground truth and retains any failure privately until reveal; a failed equality invalidates the cell. Thus even a wrong later block can rescue perfectly, and the reverse scalar effect is the negative of the forward effect here by construction. Neither property is a general rule for arbitrary nonlinear interventions. Repair is a control and a conditional intervention outcome; it does not uniquely identify the injection site or establish necessity/sufficiency for a learned behavior.

## Prespecified scoring and reporting

Primary localization: reveal the ground-truth block only after all candidate choices are frozen. For each of the 54 cells report the selected block, true block, hit/miss, and abstention. Count an abstention as a miss for overall block-hit rate while separately reporting coverage. Compare first-changed and magnitude choices with the uniform random expectation, then average the nine cell scores within each model and report all six model-level values and their equal-weight mean. A first-difference interval is evidence about the observed boundary, not the exact injected instruction. Do not count 16 held-out inputs, two strengths, or nine configurations as independent model seeds.

Primary intervention prediction: for each model `m`, cell `c`, site `j`, and predictor `q`, define `L[m,c,j,q]` as the arithmetic mean of absolute prediction errors over exactly **16 held-out inputs × 2 strengths = 32** paired effects at that same site. Compute it as `math.fsum(abs(predicted - observed) for each pair) / 32` with Python binary64 values, in case-index order and strength 0.25 then 0.75. For a selecting policy, take the `L` at its frozen selected site in each non-abstaining cell and average those cell values within the model using `statistics.fmean` in cell-index order. Report its non-abstaining count out of nine and, on those exact same cells/sites, the paired polarity-conditioned versus constant-mean and versus zero MAE differences; positive baseline-minus-conditioned means lower conditioned error. If a policy abstains in a cell there is no fabricated prediction error for that cell. If it abstains in all nine cells for a model, that model's prediction summary is undefined. Take the equal-weight mean of six model summaries using `statistics.fmean` in model-seed order only when all six are defined, and label it conditional on the stated selection coverage whenever any cell abstains. Also report per-strength and per-polarity results without changing the primary 32-case weighting.

For the uniform random-site expectation, average the three predeclared sites' `L` values within each cell, then average nine cells within each model and six model means. This is a site-distribution summary, not a valid same-outcome comparison showing that one predictor is better at a different site. Include all cases in MAE, including zero effects; do not censor low-effect cases. Report all per-case signed effects and residuals. For sign accuracy within each model, pool eligible case/strength observations across its non-abstaining selected cells, include only those where `abs(observed effect) > 1e-7`, and give the included/excluded counts and the constant predictor's sign accuracy on those same observations. A prediction within `1e-7` on an eligible nonzero effect is wrong. If all eligible effects have one sign, state that sign variation was not tested. If no eligible effects exist, sign accuracy is undefined, not zero. When sites coincide, report one intervention's observations rather than treating the policy labels as independent evidence.

Report repair separately as each patch's absolute scalar residual from `m(clean)-m(perturbed)`, together with full logits and the upstream/downstream controls; avoid division by a near-zero target. Show results for both strengths, each model seed, each injection block and operation, and both input polarities without choosing favorable subsets. Retain failed, cancelled, unblinded, masked, no-detection, and partial runs. The model seeds are six fixed initializations and the input-generation process is synthetic; this protocol specifies descriptive results for these cases, not a statistically representative model or prompt population. Do not claim significance or a calibrated population confidence interval from the six fixed seeds. A follow-on study requiring such inference must define a sampled population, randomization and an appropriate model/input clustering plan before evaluation.

## Evidence and reproducibility

Reject and retain as failed or incomplete any nonfinite trace, logit, effect, or prediction; never silently remove a nonfinite value from an aggregate. If a required cell fails, report any surviving partial summaries only as explicitly incomplete, not as complete protocol results. The result registry must retain the versioned protocol and any clarification, code and model-state hashes, commitments and reveal, the public freeze, exact per-case predictions, raw sparse traces and full output logits, all controls, root-forward counts, environment, failures, and terminal status. Never overwrite an earlier record. A fresh replay may repeat the revealed data to check reproducibility, but it is not an additional confirmation sample. An independent reviewer should verify byte hashes, phase ordering in the implementation, split disjointness including signed zero, paired metric arithmetic, unit counts, and the scope of every claim.
