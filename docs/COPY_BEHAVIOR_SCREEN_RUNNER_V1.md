# Baseline-screen CPU owner

The fixed baseline phase runs the 192 public cases once in order on the pinned offline CPU model, saving each complete 50,257-float vocabulary row before proceeding. It then scores both repeated-target top-token conditions and all six repeat/shuffle gaps per family, including every unsupported family. The screen has no intervention or outcome-dependent replacement. The two rotations score different targets; results do not isolate an order effect.

[The owner](../scripts/copy_behavior_screen_v1.py) checks the source-bound [bootstrap](../scripts/copy_behavior_screen_bootstrap_v1.py), v41 reservation, exact input/continuation tokenization, initial and final model-state/buffer/runtime identity, no hooks, full row counts and finite logits. Each row is retained before its post-return checks. Any returned partial row is recovered on a best-effort basis and the attempt remains incomplete; a hard termination or a failed recovery can leave only bytes already on disk. There is no automatic retry when launch or termination is uncertain. The [resource amendment](DISTILGPT2_COPY_BEHAVIOR_SCREEN_RESOURCE_AMENDMENT_V1.md) requires verified temporary staging on E: and its extra capacity.

The [independent stdlib reader](../audits/copy_behavior_screen/saved_independent_audit.py) reconstructs all 192 rows and the fixed support decisions from saved bytes. Before the real run it was exercised against a marked synthetic full-schema fixture with 192 rows, 38,597,376 raw bytes and 4/12 supported families in each split; its independent fake report SHA-256 is `88c3f4eab107d54154badfb07b1d370d422395dd5718df9e6d83ceef1a6aeffd`. Synthetic and production reader paths are separate. The reader checks numeric token IDs and scores, not decoded token strings or execution attestation.

The [direct-process observer](../audits/copy_behavior_screen/observe_copy_behavior_cpu_v1.py) records a fresh checkout, bootstrap command, E: temporary/staging paths, output hashes and the returned direct-child exit. The operator protects the checkout from mutation through exit. These are cooperative observations, not interpreter, clock, descendant-process or outside-exposure attestations. A lost or uncertain spawn/exit does not establish termination; retain partial evidence and do not automatically retry.

The manifest, journal, result and failure records have enforced byte caps. The observer redirects child stdout and stderr to separate files without a hard byte cap; the fixed 32 MiB metadata reserve is a preflight allowance, not a total process-write guarantee. Other runtime or filesystem overhead is likewise outside that raw-payload bound. Headroom is a point-in-time observation.

Pre-import source checking applies when the recorded bootstrap command is used under that cooperative exclusive-checkout contract. Its environment marker is caller-controlled and does not authenticate the entrypoint; direct invocation with a forged marker is outside this guarantee.
