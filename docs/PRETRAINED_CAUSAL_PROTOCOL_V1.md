# DistilGPT2 injected-change study — protocol v1

**Status: preregistration and implementation specification; not a completed experiment.** The purpose is to test whether the instrument can locate a known internal change and whether intervention effects predicted from discovery cases transfer to held-out inputs. This is a synthetic change inside a pretrained model, not an identified natural-language reasoning mechanism.

## Prerequisites and model identity

Use `distilbert/distilgpt2` at immutable revision `2290a62682d06624634c1f46a6ad5be0f47f38aa`. Verify the loader's complete pinned asset inventory, including `model.safetensors` SHA-256 `e1ff18884359fe8beb795a5f414feb85a6ce3d929ad019c0d958c039d2b94a1b` and `tokenizer.json` SHA-256 `8414cab924d8b9b33013f0d221c5862f365ee9be39c5c2bfae8a5a9e970478a6`. The pinned tokenizer maps `" the"` to token ID 262 and `" a"` to 257 with `add_special_tokens=False`. Use eval mode, float32, eager attention, batch size one, no KV cache, no generation, and no dropout. One root forward processes each unpadded prompt. Record Python, PyTorch, Transformers, device, driver, deterministic settings, source commit and hashes, and all asset digests.

The six candidate boundaries are `transformer.h.{0..5}.mlp`, specifically the output tensor before residual addition. The intervention selects batch index 0, the **last input-token position** `len(input_ids)-1`, and invocation 0 in that one forward. Record layer, full module path, output selector, local token index and invocation; do not call the last-token index a global position across generation or cached execution. The late downstream control uses the first tensor of the tuple returned by `transformer.h.5`, after that block's residual additions, at the same token. Validate the output type and selector against this pinned model before the study; reject an incompatible return shape.

**Execution is blocked until a validated composite primitive exists.** Existing independent capture/intervention sessions reject nesting on a shared model. Do not bypass that isolation. A single-owner ordered plan under an exclusive broker lease must support both capture and modification in one forward, including the same boundary. Steps across sites execute in actual model order: a patch at an earlier layer necessarily precedes the hidden injection. At the hidden boundary the required local order is injection, post-injection observation, then any same-site patch; at other boundaries observe before applying that site's patch. Verify against serial references on a known small model and test hook order, same-site injection/patch, different-site order, tuple preservation, selected-index errors, trace-byte limits, cleanup and failure of missing/duplicate requested invocations before using the pinned model. Concurrent read-only jobs may resume only after the lease and hooks are removed. This protocol records scientific work, not benchmark latency.

## Fixed inputs, secrecy and commitments

The discovery prompts are the eight literal strings in `looking_glass/pretrained_protocol.py`. A different team acting as custodian chooses a private 32-byte split nonce and derives eight distinct held-out prompts from the versioned template inventory in that file. The candidate investigator sees the public grammar and commitment, but not the selected held-out strings, token IDs, nonce, or held-out model outputs before predictions are frozen. Tokenize both splits with the pinned tokenizer, `add_special_tokens=False`, without truncation, and reject any empty or over-32-token prompt or duplicate across splits. Store exact UTF-8 text and token IDs in the private reveal record.

The custodian samples a layer uniformly from **1, 2, 3, 4** and chooses an independent private 32-byte site nonce. Layers 0 and 5 are therefore known controls rather than eligible injection sites. Before any discovery forward, publish the canonical public manifest with the salted held-out-data commitment, salted site commitment, protocol and model identifiers, discovery text/token IDs, seed and fixed configuration. The commitments bind nonce, content, model/protocol context and site; a plain hash of one of four possible sites is not an adequate blind. Save the custodian's site and nonces separately. A fixed public seed is never used to choose the hidden site or split. Save the manifest and its digest to the experiment registry before discovery and record a clearly labeled, self-reported local UTC creation time. Neither that clock nor the hash proves when a choice was made; retain an independent witness or signed external timestamp if available.

This is **procedural blinding**, not secure isolation: all agents share the same OS account and may be able to read each other's files or process state. Keep the custodian's files and worker job specs out of the investigator's normal view, report any disclosure, and label an unblinded run accordingly. The custodian must not reveal the true layer through filenames, hook logs, worker errors, timing, candidate order or device allocation. No natural-language behavior claim depends on secrecy alone.

The standard-library helper provides `heldout_prompts(split_nonce)`, `seal_manifest(discovery_ids, heldout_ids, ...)`, `canonical_sha256(public)`, and `verify_reveal(public, private)`. The custodian uses independently sampled `secrets.token_bytes(32)` nonces and `1 + secrets.randbelow(4)` for the site. Before calling `seal_manifest`, independently verify the pinned tokenizer file hash, encode each of `DISCOVERY_PROMPTS` and `heldout_prompts(split_nonce)` with `add_special_tokens=False`, and confirm the contrast IDs above. Supply the clean source commit, SHA-256 of this protocol document, measured runtime fields and self-reported UTC time. Preserve the returned public manifest and its canonical digest; keep the returned private reveal out of the checkout and the investigator's normal view. After predictions are frozen and held-out work completes, publish the reveal and check `verify_reveal` returns true. The helper checks structure and commitments only: it does not verify that supplied token IDs came from the pinned tokenizer, attest uniform sampling, protect secrets from same-account access or establish timestamps. Run from a clean source checkout and retain the exact code and protocol bytes referenced by the manifest.

## Injected change and observation

Use public seed `20261028` for perturbation direction and random-baseline choice. At the hidden site's selected MLP output, add `0.5 * d` in float32, where `d` is a 768-element sign vector with entries `+1/sqrt(768)` or `-1/sqrt(768)`. Bit `j` is bit `(j % 256)` of `SHA256(b"MLG-v1-direction" + bytes([0]) + seed.to_bytes(8, "big") + (j // 256).to_bytes(4, "big"))`, numbered from the most significant bit of each byte; 1 gives `+`, 0 gives `-`. The nominal L2 norm is 0.5. For each prompt save the realized float32 post-add-minus-pre-add vector and its norm: rounding means it need not equal the nominal delta exactly. Reject a nonfinite addition, a missing modification, or a realized vector inconsistent with float32 addition of the prescribed delta; a small or zero *downstream model effect* is a valid outcome and is not an injection failure. Do not adjust strength, site, direction, inputs or thresholds after seeing discovery outcomes.

For each prompt, compare the no-injection clean run and injected run on the **same input**. Capture each selected MLP vector after injection at its boundary, plus last-token final logits. First establish that repeated clean runs agree at all measured boundaries and logits to `abs(a-b) <= 1e-5 + 1e-5 * max(abs(a), abs(b))` elementwise on the actual backend; otherwise invalidate the run. A vector differs if any element violates that criterion. Each trace must contain exactly the ordered MLP boundaries 0 through 5, each at invocation 0, with matching token index and shape; missing, repeated, out-of-order or mismatched events invalidate the trial. A difference already at upstream layer 0 likewise invalidates it, because all eligible injections occur later. Record invocation counts, vector norms and raw difference summaries. Admit only one plan at a time on an exclusive shared-model lease; cap captured tensor payload at 1 MiB per forward and 256 MiB for the complete study, including logits and intervention snapshots. These are storage caps, not peak VRAM claims; the broker must separately reserve and monitor device memory. On overflow, cancellation or OOM retain a failure artifact and never present a partial run as success.

The discovery localization score for each eligible layer is the number of discovery prompts for which it is the **first observed differing MLP boundary**, with ties broken by lower layer index. If no eligible boundary is ever first to differ, abstain; do not select a zero-score site. Freeze the resulting ranked list and top eligible candidate; after reveal score its actual site rank, top-1 correctness and reciprocal rank. A first observed difference can only localize relative to the chosen taps. Here the perturbation is deliberately placed immediately before a tap, so this is primarily an instrumentation sanity check, not a general cause-finding result. Compare with (i) uniform random eligible layer selected once by `1 + SHA256(b"MLG-v1-random-baseline" + bytes([0]) + seed.to_bytes(8, "big"))[0] % 4`, (ii) largest mean `L2(clean activation - injected activation)` over discovery prompts, ties by lower layer, and (iii) always choose the earliest eligible layer. Each selector ranges only over layers 1–4. For one hidden site, do not interpret a single success or failure as a population accuracy estimate; the uniform-random single-trial chance is 1/4.

## Prespecified predictions and held-out intervention tests

For logits `z` at the last input token, fix the scalar `m(z) = z[262] - z[257]`. It is an arbitrary fixed next-token logit contrast, not an accuracy or language capability measure. For each eligible candidate `s` and discovery prompt `i`, use the same-input clean activation at `s` to replace the activation at `s` in an injected run. Define `e(s,i) = m(z_injected+patch_s) - m(z_injected)`. Predict the held-out effect at `s` for every held-out prompt as the unweighted mean `p_s` of the eight discovery `e(s,i)` values. Freeze all four numeric `p_s`, the candidate ranking, magnitude and random selections, and their complete discovery measurements as a separately hashed prediction artifact **before any held-out forward**. That artifact must contain the canonical public-manifest digest. If discovery fails or lacks any required case, do not tune or continue as a successful trial.

For all eight held-out prompts and all eligible sites, perform the identical intervention and compute each actual `e(s,i)`. Report per-site mean absolute error `mean_i |e(s,i)-p_s|`, root mean square error, the mean and all individual effects, and sign accuracy only among examples with `|e| > 1e-5`; give the count excluded and call sign accuracy undefined if none qualify. On those included cases, a predicted effect with `|p_s| <= 1e-5` counts as a wrong sign. Compare predicted effects with the prespecified zero-effect predictor, and report the discovery-selected candidate, random candidate and magnitude-ranked candidate separately without changing them. Prompt is the observational unit: the four site outcomes from one prompt are not four independent examples. With eight held-out prompts, treat all summaries as descriptive; no claim of reliable generalization or significance follows from them.

Evaluate restoration separately from the scalar prediction. Let `D = sum_i ||z_injected,i - z_clean,i||_2^2` and `R_s = 1 - sum_i ||z_patch_s,i - z_clean,i||_2^2 / D` over the held-out prompts and the full last-token vocabulary. If `D <= 1e-8`, report restoration undefined and the absolute numerator and denominator; never divide by a near-zero difference or select a new metric. Save per-prompt residuals, not only `R_s`. A good scalar prediction, a large `R_s`, and correct injected-site rank are distinct outcomes.

## Controls and interpretation

- **No-op/identity:** a null intervention and a same-run self-patch leave logits and captured vectors equal to their respective reference under the fixed tolerance. Failure invalidates that trial.
- **Upstream negative:** patch clean MLP output at layer 0 in the injected run. It occurs before any allowed injection; its clean and injected vectors should agree and the patch should leave the injected output unchanged under tolerance. This tests the setup, not every possible upstream causal relationship.
- **Late downstream rescue:** patch the clean final-block output at layer 5 into the injected run at the last token. Under this no-cache single-forward setup it should restore the final logits under tolerance; failure invalidates the asserted hook semantics. This is not evidence that layer 5 caused the injected change: it overwrites a downstream state carrying the consequences and can repair many distinct upstream disturbances.
- **Reverse patch:** patch the injected run's activation into the corresponding clean run at each tested site. Record the reverse scalar effect and full-logit residual; do not assume it is the algebraic negative of restoration in a nonlinear network.
- **Random and magnitude baselines:** the frozen random and magnitude candidates receive the same intervention, cases and metrics as the discovery-selected candidate. Report all results even if a baseline wins.
- **Injection integrity:** independently compute float32 `pre_add + nominal_delta` and compare it exactly with the saved post-add vector; retain their difference as the realized delta for each prompt. Confirm no other module or token is directly modified. Keep hidden-site pre/post vectors in the custodian's evidence until the blind is lifted. Restore hooks and verify a fresh clean pass after every intervention plan.

After held-out evaluation, reveal the private site, nonces, held-out texts and token IDs; independently verify both commitments and all asset hashes. Publish the manifest, frozen predictions, reveal, raw per-prompt metrics and trace metadata, source revision, environment and all failed/cancelled attempts. Never overwrite earlier evidence. The known perturbation and patch may create out-of-distribution states and can alter multiple downstream paths. A rescue establishes only the specified intervention's effect under these conditions; it does not identify a unique mechanism, prove necessity or sufficiency for a natural behavior, or establish preservation of other capabilities. See the primary studies [Towards Best Practices of Activation Patching](https://arxiv.org/abs/2309.16042) and [How to use and interpret activation patching](https://arxiv.org/abs/2404.15255) for method-dependent caveats.
