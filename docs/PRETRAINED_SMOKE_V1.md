# Pretrained GPT-2 trace correctness smoke, version 1

Status: frozen protocol for a narrowly scoped instrumentation smoke. This is not a performance benchmark, causal experiment, or general claim about transformer transparency. A prior independent CPU smoke was exploratory and is not part of this versioned run.

## Fixed inputs and implementation

- Model and tokenizer: `distilbert/distilgpt2` revision `2290a62682d06624634c1f46a6ad5be0f47f38aa`, loaded by `looking_glass.pretrained.load_distilgpt2` from a supplied local cache only. That loader verifies size and SHA-256 of each required model/tokenizer/config asset and disables remote code. Its returned verified asset hashes, immutable revision and model details are recorded.
- Use eager PyTorch, `GPT2LMHeadModel.eval()`, float32, one PyTorch intra-op thread, PyTorch seed 0, and the exact public token IDs `[464, 6766, 318, 4171, 13]`, shaped `[1,5]`; attention mask is all ones. Do not tokenize, sample, use cached generation, alter parameters, or download assets in this run.
- Two separate forward calls with identical inputs for each cell; these are not independent statistical replicates. Capture attention, MLP and block boundaries at layers 0, 2 and 5, sample position 0 and token positions 0 and 1, with a maximum of 18 events and 131,072 retained value bytes per trace session. Save value snapshots to CPU. Direct and isolated-gradient modes must retain exactly 110,592 bytes each; ID mode retains no tensor values.
- A baseline has no observation hooks. A separate forward pair installs independent reference hooks at the same boundaries and copies selected values to CPU; those logits must match the uninstrumented pair. Run direct, gradient and ID modes, each in its own exclusive adapter session. Each study gets a unique ID and each mode gets a distinct run ID; replay compares normalized identities while preserving both originals. Compare every mode's output bit-for-bit with the matching baseline output. Compare every direct/gradient captured tensor bit-for-bit against its corresponding independently captured value and against the other reporting channel. Integer views of float32 encodings are compared, since floating-point equality may treat flushed subnormals as zero. Verify event count, path/role/layer/order, output selector, original and saved shape/device/dtype, per-forward invocation index, and local sample/token positions. Expected output selectors are `(0,)` for attention and block outputs and `()` for MLP outputs.
- Any mismatch, missing target, exception, nonfinite capture, resource error or unsupported configuration fails the run. No silent retry, fallback, truncation, precision change, or reuse of an existing output directory is permitted.

## Device and memory controls

CPU and GPU are separate smoke cases, never merged as paired timings or declared bitwise-identical across devices. The CPU case is offline and requires no GPU access. The CUDA case requires a separately coordinated exclusive window and records its human-readable lease identifier; this identifier is an operator attestation, not a cross-process lock. Check device-wide free/total bytes at admission; retain the larger of 1 GiB or 15% of total as headroom, require at least 1 GiB additional free working space, and cap this process's CUDA allocator at the smaller of 1.5 GiB or the free bytes remaining beyond the reserve. Recheck the reserve after model transfer and each forward; fail rather than continue if it is breached. These checks cannot prevent other processes from changing device memory between samples and do not cap non-PyTorch allocations. Record device-wide and PyTorch allocated/reserved memory distinctly. Synchronize after each CUDA forward and before completion; timing is not collected as a result. Do not stop or interfere with unrelated applications. Release owned model/tensors, synchronize and empty this process's CUDA cache before returning.

## Output and reproducibility

The runner creates a new output directory and writes a start record; after execution it atomically publishes a success record, or attempts to publish a failure record without masking the original error. Failure evidence is best effort if imports, directory creation, disk writes, forced termination, device loss or an OS crash prevent it. A started directory with no terminal record is incomplete, never successful; existing output directories are never overwritten. Failure records redact the known checkout, cache and home paths and GPU UUIDs; raw terminal tracebacks remain local and require inspection before publication. For recorded runs, protocol and executed project sources must be committed and match the checked-out Git blobs. The record includes protocol version, fixed config, model and tokenizer asset hashes/revision, input IDs and digest, source/protocol SHA-256 hashes, source commit and relevant clean status, Python/PyTorch/Transformers and package versions, backend flags, OS, seed, and GPU/driver plus memory snapshots where applicable. It includes per-forward baseline logit hashes and ordered per-mode schema metadata and value hashes, together with explicit equality/coverage checks. It saves no raw logits, activations, model weights, or private prompts. Byte-level hashes encode contiguous little-endian float32 tensor bytes and are useful for exact replay only under a matching environment/backend and tensor interpretation; they do not support tolerance-based cross-device comparisons or reconstruction of numerical differences. A replay must distinguish mismatched environment/identity from a numerical discrepancy and repeat checks in a fresh process. The GPU identity omits physical UUIDs and cannot distinguish otherwise identical devices across hosts.

These results support only the tested one-input, short-context correctness claim. Attention output is projected attention output, not attention weights; token coordinates are local to the forwarded sequence. Matching observation does not establish a computation's causal role or reveal a model's reasoning.

Environment identity includes hashes of normalized interpreter, prefix and package-origin paths to distinguish runtime layouts without publishing absolute paths. These path fingerprints are not package-content hashes or anonymization: predictable paths can be guessed. Matching environment metadata does not establish that every hardware or runtime condition is identical.

The fixed input digest uses contiguous C-order little-endian int64 token bytes; logit and activation digests use contiguous C-order little-endian float32 bytes.

The source check compares the working-file bytes to the committed Git blob exactly. This does not attest the Python bytecode actually executed; the report explicitly records `bytecode_attested: false`. For recorded reference and replay processes, use a newly created, empty external `PYTHONPYCACHEPREFIX` and set `PYTHONDONTWRITEBYTECODE=1` before launching Python, then check that the cache remains empty. On Windows, a checkout configured to convert LF files to CRLF can therefore fail this check even if Git reports it clean; use an exact-byte/LF checkout for this protocol.

The environment records the integer bit pattern from multiplying the smallest positive float32 subnormal by one on the CPU, without changing the denormal mode. The probe distinguishes flushing in that operation but does not attest all CPU or GPU floating-point behavior. Different unmeasured modes may still make exact replay incompatible; every within-run required equality must pass regardless.
