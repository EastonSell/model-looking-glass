# Equal-length tokenizer screening reproducibility

`tests/flan_t5_equal_length_tokenizer_screen.py` is the exact original pre-forward screening script. Its original workspace-relative paths are `work/t5_length_matched/selection-plan.md` for the fixed plan, `work/t5_length_matched/` for output, and `work/t5-cache/flan-t5-small-0fc9ddf78a1e988dac52e2dac162b0ede4fd74ab` for the pinned local assets. Use a separate fresh workspace for a repeat so the original screen is retained. The script performs tokenizer-only screening and does not load model weights. The selected runner verifies the fixed plan, screen and case hashes and independently retokenizes all selected cases before model loading.

The runner records a conservative apparent-byte ceiling calculated from 936 fixed-shape returns, up to two 64 KiB forward JSON records per return, all 12 dose binaries and manifests, case and startup metadata, a bounded terminal, one malformed-return/failure allowance and an independent next-forward reserve. Per-file JSON bounds and the overall 512 MiB limit are enforced; an unexpectedly malformed return or evidence-write failure can still make the attempt incomplete. The calculation is not a reservation of filesystem blocks or a bound on transient process memory. The CUDA version would require a separate device-aware intervention/evidence path and numeric review; this study uses the already reviewed CPU path.
