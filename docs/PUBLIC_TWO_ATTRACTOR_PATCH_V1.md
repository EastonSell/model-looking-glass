# Prospective two-attractor activation-patching follow-up

This distinct public follow-up asks whether the previously selected attention-output site carries a component of the clean two-attractor interaction at the verb readout. It does not select a site from the new screen and does not claim a unique grammatical mechanism. The public natural-agreement discovery selected `3:attn:last` in `results/distilgpt2-natural-agreement-v1-20261028/natural-prediction-v2.json` (SHA-256 `eaac12d7229b2ae5615832bc9b58c7e5b2404c5866b5079295e72b0a54a4c545`); `1:attn:last` is its already frozen earliest-site comparison. These are the whole attention-module output vectors at the last input token, not individual attention heads. The earlier site is an active comparison, not a negative control.

The separate public 32-input candidate, SHA-256 `6d0cbba21d15f9ab05df106617141c25a460f07be7ee57c53470f969eb79e518`, was assembled and tokenized before this written draft, without loading the model or consulting outputs on those inputs. The initial design and the 32 cases were assembled before the separate 128-case screen completed; that screen's outcomes became available to the protocol author before this protocol was publicly frozen. The cases and sites were not selected or changed in response to those outcomes, but the final protocol was not blind to them. It uses two fresh subject pairs, both subject numbers, both orders of one fresh attractor pair and all four near/beside number combinations. Donors have the same subject and sequence length as their recipient and change exactly the designated one or two noun tokens. These inputs are disjoint from the 128-case screen by a public full-row-prefix check. They are not certified unseen in model pretraining or an unknown exposure history. Use `distilbert/distilgpt2` revision `2290a62682d06624634c1f46a6ad5be0f47f38aa`, weights SHA-256 `e1ff18884359fe8beb795a5f414feb85a6ce3d929ad019c0d958c039d2b94a1b`, tokenizer SHA-256 `8414cab924d8b9b33013f0d221c5862f365ee9be39c5c2bfae8a5a9e970478a6`, offline CPU float32 with eager attention, no gradients, no padding or truncation and `use_cache=False`. Every input is eight tokens; enforce the exact published token IDs and continuation alignment. Before any model forward, freeze and publish the final protocol, exact cases and implementation, check the latest public exposure and protected public-support sets, and use the existing planned-input reservation process. No old protected record or nonce is used.

For each of the eight fixed subject-lemma, subject-number and attractor-order units, define four clean cases with near/beside noun number either matching (0) or mismatching (1) the subject. Let `M_ab` be the signed final-position logit difference `is − are` (sign +1 for a singular subject, −1 for a plural subject). The clean interaction is `I_clean = M_11 − M_10 − M_01 + M_00`. Accuracy means a strictly positive signed pairwise `is − are` margin; ties are reported separately and counted as incorrect. This is not a full-vocabulary top-token claim. Keep wrong and tied clean cases; there is no eligibility filter, reselection or success threshold. Apply the same pairwise rule to secondary `was − were`.

Capture clean site outputs for all four input cases. At each of the two fixed sites, run the all-congruent `00` recipient with three activation replacements: donor `10` (near noun only), `01` (beside noun only), or `11` (both). For each, define `δ_ab = M_patched(00 ← ab) − M_clean(00)`. Define `I_patch = δ_11 − δ_10 − δ_01` and report the paired difference `I_patch − I_clean`. Also report each `δ`, clean cell margin, clean and patched accuracy, and each unit separately, with descriptive means by subject number, subject lemma, order and site. Report the L2 displacement of each donor vector from the recipient at the patch coordinate; do not equate the different donors' effective doses.

At each site and unit, an unchanged-input no-op and same-input self-patch must leave selected float32 logits bitwise equal to the corresponding clean `00` logits. Capture the target site before and after the action; verify the post-action selected vector equals the intended donor bitwise and that other positions of the module output remain bitwise unchanged. Retain raw float32 donor vectors, full target module outputs before and after each action, raw selected clean/patch logits, module path/token coordinate, shapes, and process outcome so the norms, landing and unchanged-position controls can be independently reconstructed. Require finite logits and activation payloads, expected 768-element selected vectors and `[1, 8, 768]` full outputs, and no more than 16 MiB of retained raw tensor bytes. A missing control or incomplete run prevents treating that unit as an assessed intervention; retain partial evidence. There are 32 clean input captures and 80 target runs (two sites × eight units × no-op, self, three donor patches), for 112 planned forwards if captures at the two sites share each clean forward.

The patch coordinate is position 7, the final beside-noun token itself. A beside-only or double donor changes the lexical identity at that coordinate, so its effect includes a direct local-lexical contribution; positional differences do not isolate independent contextual channels. Whole-vector replacement carries every difference in the donor's contextual activation; downstream nonlinearities can create or remove interaction. Similarity or difference between `I_patch` and `I_clean` therefore does not establish independent attractor representations or a unique causal mechanism. This small, single-template design has no significance or population claim and does not vary syntactic attachment independently. Selection of these two sites was based on earlier public discovery, not on these test cases.
