# Private known-injection forward witnesses

`looking_glass.pretrained_number_witness` provides a bounded private
serialization and a consistency audit for one **completed** CPU forward of
the known-injection track. Its data contain the hidden layer, full pre/post
module outputs, donor bits, realized deltas and plan ordinals. Keep all such
records, exceptions and decoded objects in the custodian's private context
until the protocol permits reveal. This is procedural confidentiality, not a
security boundary against same-process or same-account code.

For each planned action, the audit checks its exact module, invocation,
selector and order metadata; complete full-output pre/post snapshots; unchanged
unselected tokens; exact selected float32 add or donor/null landing; adjacent
same-site actions; public post-action captures; and the recorded binary64
realized delta recomputed from the original float32 bits. It compares the
selected pre-add vector and upstream boundaries with the same-input clean
baseline using the protocol tolerance. Repeat, final-clean, upstream,
downstream, null and self controls are checked against their appropriate
baseline. Private record decoding is bounded to 1 MiB of canonical JSON and
binds the record's role, request, input digest and condition to the supplied
public observation before audit. The completed-forward format rejects missing
or duplicate role-required actions, but successful encoding alone is not proof
of a completed forward: the private audit and a separate execution supervisor
must establish the required checks. Partial-failure evidence needs its own
explicit incomplete record format.

These routines do not write a file, journal interrupted work, manage a model or
prove that any supplied bytes were generated by a real forward. A trusted
custodian must independently bind every clean/injected baseline and candidate
to the matching prepublished request plan and durable public archive; a
self-consistent forged baseline and witness can satisfy this audit. It must
verify the exact checkpoint, source, runtime, module settings and model state,
maintain exclusive trusted execution, and enforce all study phases. Model and
module checks before and after execution cannot rule out transient unobserved
changes inside an attempt. This single-forward audit does not justify the
selector's whole-study private-controls attestation by itself.

For failures, preserve all earlier completed records and any available bounded
partial evidence in a separate durable journal; the current executor may discard
uncommitted failed-forward captures. Its private exception type/message are
bounded and may be truncated or unavailable, so a supervisor must not present
them as complete diagnostics. A failed recording or unknown cleanup leaves the
attempt incomplete and the worker quarantined. Serialization tests use only
toy CPU models and synthetic inputs, not pretrained or held-out study runs.
