# Supported fault coverage and experimental opcode probes

Python documents that exceptions escaping an opcode trace callback into the traced function can produce undefined interpreter behavior. This is a limitation of the injection mechanism, not evidence that ordinary application exceptions or cancellation are unsupported. See [Python 3.12 `frame.f_trace_opcodes`](https://docs.python.org/3.12/reference/datamodel.html#frame.f_trace_opcodes).

The exact manifest contains **57 exception-raising opcode probes** in the explicit opt-in, subprocess-isolated group. An opt-in assertion failure, abnormal exit, or timeout remains a failed experimental probe; it is not converted to a successful test. Default-suite results must report excluded probe counts separately. The manifest is `tests/experimental_opcode_faults.json`. Run opted-in probes with `python -m pytest --run-experimental-opcode-faults`; use `--experimental-opcode-timeout=60` (default: 60 seconds per child). This boundary is implemented by pytest: direct unittest execution bypasses it. On POSIX, timeout cleanup targets only the child's newly owned process group; other platforms guarantee direct-child cleanup only. The child-process boundary is not a security sandbox or proof of real GPU cleanup.

## Ordinary fault controls that should remain in the default CPU suite

These examples were inspected in source. They inject faults at normal Python call boundaries or use synchronization events rather than throwing from opcode callbacks:

| Area | Existing controls and assertions |
|---|---|
| Worker admission and drain | `tests/test_budgeted_worker.py`: `test_running_cancellation_keeps_lease_until_worker_is_drained` retains the lease until the blocked forward exits, then releases it; `test_oom_after_verified_drain_releases_lease_but_poisoned_worker_stays_unavailable` distinguishes resource release from reuse eligibility; `test_failed_synchronization_quarantines_lease_and_all_wrappers_on_device` keeps the lease and rejects another wrapper on that device. |
| Weight-edit rollback | `tests/test_targeted_edit_v2_candidate_safety.py`: `test_interrupted_candidate_restores_hooks_and_flags_before_propagating` raises from the model's forward callback and verifies hook/flag restoration. `test_hook_removal_failure_in_normal_context_propagates` checks a failing removal callback. |
| Partial evaluation evidence | `tests/test_targeted_edit_v2_evaluation_owner.py`: `test_partial_condition_stops_without_a_success_terminal` covers state-write failure before/after bytes, lost condition acknowledgement, and edited-row failure; it verifies original weight restoration, cleanup state, retained partial files, and absence of a success terminal. |
| Trace-store memory accounting | `tests/test_trace_store.py`: `test_context_and_copy_failure_release_claims` checks ordinary context error and clone callback cancellation; `test_cancelling_inflight_copy_keeps_claim_until_acknowledged` blocks a clone, cancels concurrently, keeps the charged claim until acknowledgement, then confirms capacity becomes reusable. |
| Handoff uncertainty | `tests/test_trace_handoff_recovery.py`: `test_lost_pin_return_keeps_claims_and_requires_supervision` and `test_lost_inventory_reservation_return_keeps_exact_guard` raise from wrapper calls after registration; both retain exact custody/accounting and reject blind retry. |
| Service quarantine | `tests/test_gpu_service.py`: `test_synchronization_failure_prevents_attestation`, `test_failed_drain_latches_and_retains_resources_until_process_exit`, and `test_failed_drain_retains_known_resources_if_error_bookkeeping_ooms` verify no clean attestation, persistent poison, retained references/leases, and rejection of a new owner following an unverified drain. |

Ordinary commit-custody synchronization controls pause normal attribute publication and lock exit, without opcode tracing. They retain blocked-cancellation, claimed-byte, active-commit and weak-reference release checks. Harmless opcode-observation/helper controls are a separate category. For example, `tests/test_opcode_support.py::OpcodeTraceSupportTests::test_prior_tracer_is_restored_when_traced_call_raises` raises in the target function, not in its tracing callback, and checks restoration of the prior tracer. Merely mentioning `f_trace_opcodes` does not justify excluding a whole file or test family.

This inventory is source-review evidence, not a new passing test run. It does not prove all possible interruption points safe, real CUDA/Windows cleanup, or the scientific validity of model findings. Default green results remain scoped to the supported runtime and tests actually executed.
