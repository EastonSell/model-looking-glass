# Full-top study: prospective stage-bound source clarification

This note records a prospective deviation from the source-ordering language in
`TARGETED_EDIT_FULL_TOP_CPU_V1.md` and the earlier scope clarification. The
published protocol calls for an executable source revision and manifest before
the first baseline screen. The baseline screen owner and its selection,
numerical matching and scoring helpers have been implemented and reviewed;
the development and edited-evaluation execution owners have not yet been
implemented. The case proposal was already assembled and reviewed when this
clarification was written. No full-top proposed input has been forwarded through
the model, and no baseline screen scores have been observed.

Before the first screen forward, publish and independently review the exact
screen source and a manifest binding all 48 cases, the fixed screening and
selection rule, scientific grids and thresholds, random seeds, checkpoint,
tokenizer, runtime and relevant custody. Publish this clarification in the
same ancestry. The publicly reviewed numerical and scoring helper blobs are
part of that pre-screen source. Preserve those exact blobs in later phase source
maps; identify and independently review any later correction as a post-screen
change, with its rationale and effect.

If the screen is eligible, development and evaluation execution owners may be
implemented after the baseline outputs are known. Therefore their code is not
fully preregistered before the screen: baseline outcomes may inform its
implementation. The evaluation executor may also be written after development
outputs are known, so those measurements may inform its implementation. Before
the first forward of each later phase, publish and
independently review that phase's exact source revision and manifest, binding the
published screen selection, fixed case identities, prior evidence and phase
inputs. Publish the complete development and dose-selection record before any
edited evaluation forward. No later implementation or review authorizes a
change to the published selection, grids, seeds, matching criteria, held-out
rules, thresholds or terminal classifications. A substantive method change
requires a separately disclosed prospective protocol, not a silent revision.

All 36 screen rows and unsuccessful or underfilled results remain evidence;
there is no redraw, replacement, threshold relaxation or retuning on evaluation
outputs. Invalid or uncertain source, forward, restoration, custody or cleanup
continues to override numerical labels as incomplete. A valid underfilled screen
remains ineligible. A no-match result retains the separately specified
unavailable comparison and descriptive outcomes. Git ancestry, process records
and clock observations provide cooperative evidence of reported ordering, not
authenticated proof of execution or time.
