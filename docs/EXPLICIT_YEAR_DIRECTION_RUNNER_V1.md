# Explicit year-direction CPU runner

`scripts/explicit_year_direction_v1.py` implements the fixed public
[protocol](DISTILGPT2_EXPLICIT_YEAR_DIRECTION_V1.md) and the separately
published cases. It verifies the reviewed v21 reservation for all 48 rows.
Before any pretrained forward, publish the exact executor and pre-run record
and check the latest reviewed public exposure history.
Unknown outside and pretraining exposure remain unverified.

The runner records 48 unhooked clean and 48 passive no-op forwards, checks
the saved position-zero captures and reports the strict comparator gate. It
then runs all four rotated actions and a clean-after for every case regardless
of that gate, for 336 forwards. A failed comparator gate makes the
comparator-like intervention decisions ineligible; the independently
predeclared generic-shift pattern is still evaluated. It preserves every
family and both donor directions, including negative outcomes.

The family-wide dose, software float32 delivery and full block-output witness
reuse the reviewed year-transfer intervention mechanism. Wording names are
mapped to the existing planner and mapped back before records are saved.
Each planned site and actual before/after tensor is retained; all other
coordinates must be unchanged and the achieved dose is recomputed from that
same invocation. Exact clean/no-op/self/clean-after full-logit equality and
hook removal are required. Scores decode the stored float32 bit patterns to
binary64 before the fixed local and pair-band contrasts and full-vocabulary
mass calculations.

The process uses pinned cached weights, CPU float32, eager no-cache execution,
one intra-op thread, a fixed CPU RNG seed and cooperative CUDA/network guards.
It records source, dependency, environment, model, buffer and runtime
identities and verifies the clean source set. Raw retained payloads have an
aggregate 114,731,328-byte bound plus separate per-forward and metadata caps;
those limits are not a bound on total process memory.

Returned bounded payloads are written and journaled before later checks. On a
helper or post-return failure, available bounded bytes are preserved in a
separate partial file when capacity permits; any incomplete original write
remains intact. Failure records inventory those files and any partial-save
error. A false return-observation flag means the return was not observed, not
that it was proved absent. Failed attempts are incomplete and are not
automatically retried. An external direct-process receipt and independent
saved-byte replay are required before reporting a result.
