# FLAN-T5 sentiment behavior: prospective development screen (draft)

## Purpose and status

This is a model-free, prospective draft. It fixes a small public development screen before any model output is read. The question is whether the pinned `google/flan-t5-small` checkpoint produces the requested positive/negative labels on short, explicitly evaluative reviews. This is distinct from the prior English–German teacher-forced study, whose held-out primary was inconclusive. The screen is exploratory and is not the later intervention test. Its examples, outputs, failed baselines, tokenizer records and the full candidate inventory will be exposed development evidence. No protected or held-out data are requested or consumed here. Do not treat model pretraining exposure as known.

## Fixed development inputs

Use the following two exact instructions, followed by one ASCII space and the review. The second is grammatically also interpretable as a yes/no question, so its strict score includes output-format compliance:

1. `Classify the sentiment of this review as positive or negative:`
2. `Is this review positive or negative?`

Use each of the four exact subjects `book`, `movie`, `meal`, `service`, with review `The {subject} was {adjective}.` Use both sides, in order, of all four adjective pairs:

1. `wonderful` / `awful`
2. `excellent` / `terrible`
3. `amazing` / `horrible`
4. `enjoyable` / `disappointing`

The fixed list is the Cartesian product in instruction, subject, pair, then positive/negative order: 2 × 4 × 4 × 2 = 64 inputs. The designated labels are respectively `positive` and `negative`. The natural-language meaning and target must be reviewed before execution. Do not substitute, discard, add or reorder examples in response to model outcomes. Record exact UTF-8 text, token IDs, masks, special-token masks and offsets. A word split by the tokenizer stays in the screen and is simply not eligible for a later *single-token* intervention.

## Execution and observation

Require the same seven-file manifest and checkpoint revision used in the published FLAN held-out study. Run offline with CUDA hidden, float32, deterministic algorithms, eager attention, one intra/inter-op thread, cache disabled and a fixed seed. Persist source, asset, runtime, inputs and generated IDs. Use a plain greedy autoregressive loop: start with decoder-start ID 0, forward the complete prefix without cache, append the lowest-ID argmax of the *raw* final-position vocabulary logits (ties resolve to the smallest ID), and stop on emitted EOS ID 1 or after four new tokens. Apply no forced EOS/BOS, suppression, minimum length, repetition penalty, sampling or other logits processor. The decoder-start ID is input, not an emitted token. Save each prefix, raw full-vocabulary float32 logits and emitted ID, and distinguish actually emitted EOS from truncation. This explicit loop does not rely on implicit `generate()` defaults.

Encode each input once and reuse that exact encoder output for its generation and label decoder calls; decoder key/value caching remains disabled. Every decoder prefix receives an explicit all-one attention mask, including the start token and any emitted pad token. Separately tokenize `positive` and `negative` with `add_special_tokens=False`, reject empty, identical or special/unknown lexical ID sequences, append exactly one EOS, record both target IDs/masks, and teacher-force each complete sequence from decoder-start 0, saving its full-vocabulary logits and float32 per-token log probabilities. Sum those recorded values with Python `math.fsum` in binary64. The difference of their summed scores is a log probability ratio between these two exact complete sequences, not a calibrated class probability or generated answer; do not assume their first lexical IDs differ or call a shared first-token rank discriminating. Save every completed case immediately, including wrong or truncated generations. An exception, missing logit payload or uncertain forward makes the attempt incomplete; retain partial evidence and do not promise further forwards after an uncertain execution failure. A direct parent observes process exit and retains all partial records. No model intervention is run in this screen.

After the 64 cases, rerun the first enumerated input of each instruction. Require exact equality of generated IDs, all raw generation-step logits, and both teacher-forced label/EOS logits versus the original case. Failure or missing repeat makes the screen incomplete, not a behavioral miss. The no-cache number of model forwards depends on the actual generation length; record each completed step and enforce a fixed upper bound of 66 × (one encoder call + four generation decoder calls + two teacher-forced decoder calls), with no retries. Bound an input to 64 tokens, each full target to five tokens including EOS, and the journal plus raw payloads to 128 MiB; reserve space for a failure marker separately. The journal records forward starts, completed raw tensor references and completed cases, allowing an open or interrupted forward to remain visible. These logical retained-data limits are not a process-memory bound.

For the strict screen, a generated response is correct only when it has exactly one terminating emitted EOS within the cap, contains no other special, pad, unknown or sentinel token, and its decoded pre-EOS text, after Unicode NFC normalization, outer whitespace stripping and case folding, is exactly the assigned bare label. Decode without skipping special tokens or cleanup of tokenization spaces, and store the unmodified decoded text as well. Any other output, punctuation, added explanation or truncation is not strictly correct and remains in the denominator; it may be described separately without changing the rule. Record both label sequence scores for every completed generation, including wrong or truncated responses. Ranks use a fixed minimum-rank convention: one plus the number of strictly higher logits.

## Prespecified feasibility rule

A **complete pair** means both adjective-side inputs for one instruction, subject and pair yield their assigned strict greedy labels. This screen supports the proposed prospective locally held-out intervention planning only if all 64 outputs are recorded, the clean repeats agree, at least 24 of 32 pairs are complete, at least 10 of 16 pairs per instruction are complete, and each adjective pair and each subject has at least 4 of 8 complete contexts. Report every pair, both class-level 32-case accuracies and counts per instruction, adjective pair and subject regardless of this rule. These are practical go/no-go thresholds chosen for a bounded exploratory study, not inferential tests; 32 contexts share four adjective contrasts. A failure leaves the entire screen published, with no silent replacement or cherry-picked primary subset. It does not preclude a separately proposed, explicitly post-screen descriptive follow-up.

## Candidate intervention question (not yet a frozen test)

Report tokenizer-only counts for adjective pairs with both words exactly one aligned token and viable distinct same-polarity single-token donor words, with equal complete input lengths, masks, valid word offsets and token differences restricted to the intended adjective token. For this conservative diagnostic, the single attended non-special token's offset must equal the adjective's exact character span; a tokenizer offset that includes surrounding whitespace is ineligible even if stripping it gives the adjective. The relevant screen inputs must also have documented clean behavior; a behavioral pass alone does not guarantee a feasible intervention. If feasible, ask whether changing the encoder final-layer-normalized state at a sentiment adjective toward a polarity-flipped donor changes generated label and teacher-forced label margin more than a same-polarity lexical-donor control and other location controls, at a common **achieved** input L2 displacement. Two directions, multiple nonzero doses, the exact clean baselines and full outputs would be retained. The same-polarity donor is not a proven inert control: different words and off-manifold substitutions may have different functional effects. A large matched control, negative/near-zero result, absence of output reversal, or a change only in the restricted pairwise score would each remain a substantive result. A result would describe an intervention effect at a chosen site, not unique sentiment localization or a complete mechanism.

After the development screen and its independent review, freeze a separate detailed protocol, intervention source, fixed cases, control donors, numerical decision and audit before observing any test-case outputs. The later cases must have independent locally held-out custody/commitment and checked non-overlap of exact inputs and variable lexical material with all known prior FLAN prompts and candidates, including this complete screen; shared task boilerplate and output-label words are not themselves claimed unseen. No claim of independence from training follows. Specify the baseline condition, full denominator and how unsupported test pairs remain visible without replacement before running. Consult the current custodian of any protected split before comparison or forward. A passing development screen does not imply that the prospective set will pass.

## Rationale

The prior [held-out report](https://github.com/EastonSell/model-looking-glass/tree/da9ab5e/results/flan-t5-heldout-response-cpu-v1-20261029) was inconclusive on its primary gate; its descriptive results and complete revealed pool remain development evidence. The FLAN-T5 checkpoint was instruction tuned, but the [FLAN paper](https://arxiv.org/abs/2210.11416) does not establish this small checkpoint's behavior on these prompts. [Zhang and Nanda](https://arxiv.org/abs/2309.16042) show activation-patching results can depend on metrics and intervention choices; comparisons therefore include actual generation, full outputs, polarity-preserving donors and exact achieved doses. Selection of this small, constructed prompt set does not support population inference.
