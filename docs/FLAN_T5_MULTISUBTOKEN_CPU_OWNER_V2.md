## Evidence and limits

The operator runs story, concert and painting in that fixed order, with separate direct children and journals. It starts no study work until it has the direct-child handle, bounded log drainers and a spawn record. If no discovery groups are selected, it records `no-selected-groups` without loading the checkpoint. If painting has no eligible groups, its no-model status is retained separately. The initial `owner_contract` records the input binding, runtime versions and CPU settings; the model uses pinned local files, deterministic CPU execution and no cache.

Each pass retains its `started.json`, event journal, raw returned tensors and terminal. `owner-receipt.json` binds the saved terminal and events to the selected source and input binding. `operator-exit.json` records the direct child's exit, reaping, bounded log hashes and whether those saved records reconcile. `operator-summary.json` is still provisional and must be checked against the separately observed outer exit and independent replay. Preserve partial records on failures; do not retry an uncertain attempt or replace its selected cases. PID-bearing spawn records and logs should stay private or be explicitly redacted before publication.

The stdin gate is not a parent-death watchdog. A granted child can outlive a killed parent, and waiting for the direct child does not prove that no escaped descendant exists. If cleanup or reaping is uncertain, establish the actual process state before further work and retain the attempt. Git and file hashes establish saved-byte consistency, not authenticated execution or native-library identity. The generated-output and score comparisons test the specified final-subtoken intervention and controls, not a whole-word substitution or a universal null.
