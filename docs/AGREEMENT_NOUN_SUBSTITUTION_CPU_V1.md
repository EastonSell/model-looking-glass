# Noun-substitution CPU owner

The fixed public protocol, 54 input rows, and planned exposure reservation
are pinned by `tools/agreement_substitution_cpu_v1.py`. The reservation records
planned inputs only. Before model work the caller must establish the separately
observed current inventory and custodian status, bind the exact published
owner source and command, and complete a model-free supervised rehearsal.

The worker reuses the earlier reviewed direction runner, delivery and journal
primitives, with a separately checked 486-action schedule and a 256 MiB
retained-tensor, 32 MiB event-log, 4 MiB per-forward and 512 MiB post-run
apparent-attempt limit. The last limit sums file lengths and does not measure
allocated storage. The operator separately measures allocated file bytes at
closure. A failed full-sequence output and rejected candidate remain
reservable. These bounds are not a live OS disk quota. The entry checks
2 GiB output and 512 MiB cache staging, jointly when they share a volume,
before the one-shot claim. These checks are point-in-time observations.

To conserve disk, this owner is developed in the previous small checkout. Its
source revision need not descend from the newer protocol/case/reservation
commits. The entry must instead compare its checkout files to the exact
independently observed published Git blobs, reconstruct the source-bound
reservation and latest pinned inventory, and bind a separate operator
currentness observation. It verifies the prior direction ancestor and
checkout-wide captured Python source against the exact owner revision. The
operator must independently establish the public commits and currentness;
neither a Git blob check nor an operator receipt authenticates execution.

The reviewed gated direct-child supervisor is required. It gives a cooperative
direct-child identity and a one-shot grant before model work; no descendant
drain or OS-enforced quota is claimed. A result requires an observed clean
parent exit and independent replay of a closed journal. Any error,
interruption, unavailable comparison or uncertain launch remains incomplete
and is not retried. Before any model forward, freeze and review the exact
owner sources, published planned reservation, current public inventory,
natural/injection custodian reports, disk observation and command. The
inherited earlier output-reference vector is loaded only as a pinned
provenance asset and is not a primary comparison in this protocol.

The entry accepts `--prelaunch`, `--prelaunch-sha256`, `--latest-exposure`,
`--operator-exposure`, `--operator-observation`, `--natural-observation`,
`--injection-observation`, `--case-file`, `--direction-dir`, `--reference-file`,
`--reference-manifest`, `--cache-dir`, `--output-dir`, `--study-root`, `--venv`
and `--child-custody`. `--validate-only` checks the source and public input
bindings without loading the model, forwarding cases, or creating a case
claim. The inherited output reference is verified as provenance, not used by
the worker's primary statistics. The fixed case-bound claim and incomplete
evidence must remain in the chosen persistent custody root.
