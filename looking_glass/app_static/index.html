Use a Hugging Face folder with config, tokenizer or image processor, and safetensors weights. No model downloads or custom checkpoint code.

Checking actual device availability…

CUDA preflight and synchronized checks accompany a scoped PyTorch caching-allocator cap. A stricter existing cap is preserved and restored afterward. This is not a total-VRAM guarantee: driver/context and non-PyTorch allocations are outside it. Full captured vectors are copied to CPU RAM. CPU execution ignores this allowance.

No model loaded.

Float32: GPT-2 and T5 support CPU or one CUDA GPU. Auto uses CUDA for GPT-2/T5 when available and CPU for DistilBERT masked language models or ViT image classifiers, with the device-selection reason recorded. No half-precision, multi-GPU sharding, GGUF, or custom-model support.

Reopen a saved capture

Read a previously saved safetensors + JSON export into RAM without loading its model. Never open pickle checkpoints or traces.

Capture settings

Auto uses direct forward hooks to copy full vectors at supported module outputs, not every operation or neuron. Rounding-based or gradient gates are separate experiments, not this capture mode. Hooks affect this runtime session, not the checkpoint.

Module outputs

Leave blank for every supported layer. Captured vectors still retain their full feature dimension.

Limits reject oversized work; they do not silently truncate captures. The CPU capture budget counts retained tensor bytes, not GPU model memory, model weights, temporary copy buffers, or peak process RAM. Full uncached generation repeats work at each step.

Nothing saved automatically

Prompts, outputs, and captures stay in this local process unless you choose Save capture. Approximate viewing does not discard the original vectors. Clearing a run releases the app’s references; it is not secure memory erasure.
