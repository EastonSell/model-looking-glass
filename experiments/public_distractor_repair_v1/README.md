# Public distractor/downstream repair runner

This code implements the fixed [public protocol](../../docs/PUBLIC_DISTRACTOR_DOWNSTREAM_REPAIR_V1.md) on the 16 already published cases. The selection function receives only numeric candidate effects; the injection roles and candidate mapping remain public. The primary held-out outcome is a ratio of mean full-vocabulary distances for a distinct downstream clean-vector patch. The process does not access the protected old split.

The direct child runs CPU float32/eager evaluation with a fixed checkpoint and verified local staging. It records full logits at both positions, ordered trace/hook metadata, per-action float32 witnesses and the three downstream binary64 realized displacement vectors per case. The admission check binds the historical v38 reservation; a separate operator observation binds the latest relevant public inventory immediately before launch. The randomized CPU model fixture is produced with `python make_fake_fixture.py` and contains no pretrained data. With a fresh fixture beside these scripts, `test_distractor_core.py`, `test_distractor_executor.py`, `test_distractor_analysis.py`, `test_distractor_saved.py`, `test_direct_launch.py` and `test_run_phase.py` exercise fixed rules and failure cases. Set `PUBLIC_DISTRACTOR_FIXTURE` to use an equivalent fixture elsewhere.

The Windows thread rounding mode is inspected before and after relevant calculations; float64-to-float32 conversion uses integer nearest-even arithmetic. This assumes a trusted interpreter and native libraries that do not concurrently alter the thread mode. No saved record or cooperative direct-child receipt authenticates all execution or descendants. An absent receipt or uncertain child state is not a completed phase and does not permit an automatic retry. Public input comparisons do not establish disjointness from unknown external or pretraining exposure.
